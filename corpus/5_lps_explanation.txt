Title: Longest Prefix Suffix Table
Author: Algorithm Research Collection
Category: String Algorithms
Year: 2026
Content: The LPS table stores the length of the longest proper prefix of the pattern that is also a suffix for every pattern position. When two characters mismatch, the search uses the previous LPS value to decide how far the pattern can move. This is the central preprocessing step of KMP.

1. Theoretical Foundations and Historical Context
The Longest Prefix Suffix (LPS) array, also historically termed the failure function or pi-table, was invented by Knuth, Morris, and Pratt in 1977.
Its discovery stemmed from analyzing the inefficiency of naive string searching, which redundantly re-compares characters already inspected.
James H. Morris conceived the idea in 1969 while writing a text editor for the CDC 6400, independently discovered by Donald Knuth and Vaughan Pratt.
The LPS array mathematical structure reflects the deterministic finite automaton (DFA) transitions for string recognition without backtrack.
In modern search engines and DNA bioinformatics, the LPS array represents the foundational preprocessing artifact for linear-time pattern matching.
Within our Digital Library Search System, the LPS table enables deterministic sub-millisecond full-text document searches across thousands of records.
Understanding the construction of the LPS array is essential for mastering linear-time string algorithms.

2. Core Principles, Data Structures, and Invariants
Definition of LPS[i]: The length of the longest proper prefix of pattern[0..i] that is also a suffix of pattern[0..i].
Proper Prefix and Proper Suffix: A proper prefix cannot be the entire string; similarly, a proper suffix excludes the full string itself.
Self-Similarity Exploitation: When a mismatch occurs at pattern[j], the previous j characters have already matched the text.
No Text Backtracking: The text pointer i moves strictly forward monotonically; the pattern pointer j retreats to LPS[j-1].
Linear Construction Bound: The LPS array itself is constructed in O(m) time where m is pattern length, using the same prefix-suffix reuse logic.
State Machine Analogy: The LPS array defines the failure fallback transitions of a finite state transducer recognizing the search pattern.
Two-Pointer Maintenance: Construction maintains pointer `len` (current longest prefix suffix) and scanner pointer `i` from 1 to m-1.
Recursive Fallback Invariant: When pattern[i] != pattern[len], fallback to `len = LPS[len-1]` checks progressively shorter matching prefixes.
In digital libraries, preprocessing user query strings into LPS tables ensures instant keyword filtering across massive bibliographic corpuses.
The algorithm guarantees that zero previously matched characters in the corpus are ever re-evaluated.

3. Mathematical Analysis and Asymptotic Bounds
Formal LPS Definition: LPS[i] = max { k : 0 <= k < i+1 and pattern[0..k-1] == pattern[i-k+1..i] }.
Base Case: LPS[0] = 0, because a single character has no non-empty proper prefix.
Upper Bound on Growth: LPS[i] <= LPS[i-1] + 1; the length can increase by at most 1 per character step.
Amortized Construction Complexity: In the while loop, `len` decreases by at least 1 at each failure fallback; total increments of `len` are at most m-1; hence total comparisons <= 2m = O(m).
Space Complexity: Exactly O(m) auxiliary storage for the integer array of size m.
Periodicity and Repeating Substrings: If m % (m - LPS[m-1]) == 0 and LPS[m-1] > 0, then pattern has a repeating unit of length m - LPS[m-1].
Search Phase Bound: Total character comparisons in KMP search using LPS array is strictly bounded by 2n = O(n).

4. Algorithmic Procedure and Execution Workflow
Procedure Compute-LPS-Array(pattern, m):
  1. Allocate integer array LPS of size m; LPS[0] = 0.
  2. Initialize len = 0 // Length of previous longest prefix suffix.
  3. Initialize i = 1 // Scanner index from second character.
  4. While i < m:
       If pattern[i] == pattern[len]:
         len = len + 1.
         LPS[i] = len.
         i = i + 1.
       Else: // Mismatch encountered
         If len != 0:
           len = LPS[len - 1] // Fall back to shorter matching prefix, do NOT increment i.
         Else: // No matching prefix available
           LPS[i] = 0.
           i = i + 1.
  5. Return LPS array // Precomputed failure function.

Step-by-Step LPS Computation Trace for Pattern 'ABABCABAB':

i=2, len=0: pattern[2] ('A') == pattern[0] ('A') -> len=1, LPS[2]=1, i=3.
i=3, len=1: pattern[3] ('B') == pattern[1] ('B') -> len=2, LPS[3]=2, i=4.
i=4, len=2: pattern[4] ('C') != pattern[2] ('A') -> len=LPS[1]=0 (fallback).
i=4, len=0: pattern[4] ('C') != pattern[0] ('A') -> len==0 -> LPS[4]=0, i=5.
i=5, len=0: pattern[5] ('A') == pattern[0] ('A') -> len=1, LPS[5]=1, i=6.
i=6, len=1: pattern[6] ('B') == pattern[1] ('B') -> len=2, LPS[6]=2, i=7.
i=7, len=2: pattern[7] ('A') != pattern[2] ('A') -> wait, pattern[7]=='A' == pattern[2]=='A' -> len=3, LPS[7]=3, i=8.
i=8, len=3: pattern[8] ('B') == pattern[3] ('B') -> len=4, LPS[8]=4, i=9.

7. Comparative Analysis and Architectural Trade-offs
LPS Table (KMP) vs Bad Character Rule (Boyer-Moore): LPS shifts pattern forward based on prefix-suffix alignment; Boyer-Moore scans right-to-left skipping up to pattern length characters.
LPS Table vs Naive Re-scanning: Naive search re-evaluates characters upon mismatch leading to O(n*m) worst-case; LPS eliminates backtracking guaranteeing O(n+m).
LPS Table vs Suffix Automaton: LPS represents 1D linear array for a single fixed pattern; Suffix Automata process arbitrary substring queries over fixed corpora in O(|query|).
Preprocessing Overhead: LPS requires only O(m) time and space, making it vastly lighter to build than full generalized suffix trees.

8. Common Misconceptions, Pitfalls, and Edge Cases
Incrementing `i` on Mismatch Fallback: Incrementing scanner pointer `i` while falling back `len = LPS[len-1]` causes characters to be skipped prematurely.
Off-By-One Indexing Errors: Forgetting that LPS[0] is always 0 and comparing pattern[i] against pattern[len] instead of pattern[len-1].
Assuming LPS Includes Entire String: Mistakenly counting the full string as a prefix suffix; by definition, proper prefixes must be strictly shorter than the string.
Memory Leak on Re-instantiation: Reallocating new LPS arrays for every document search instead of precomputing once per user query.

9. Frequently Asked Questions (FAQ)
Q: Why is LPS[0] always zero?
A: Because a prefix or suffix must be 'proper' (strictly shorter than the string itself); for a single character string, the only proper prefix is the empty string, length 0.
Q: What does LPS value 4 at index 8 mean in 'ABABCABAB'?
A: It means the substring 'ABABCABAB' has a 4-character prefix 'ABAB' that matches its 4-character suffix 'ABAB'.
Q: Does KMP search ever move the document text pointer backward?
A: Never. The text pointer moves strictly forward monotonically from 0 to N-1, ensuring linear-time O(N) guarantees.
Q: Can the LPS array be used for circular string matching?
A: Yes, by concatenating the string with itself (S + S) and searching for pattern P using the LPS array.
