Title: Finding Multiple Pattern Occurrences
Author: String Processing Research Group
Category: String Algorithms
Year: 2026
Content: A pattern may occur several times in one document. After KMP finds an occurrence, it uses the corresponding LPS value and continues searching. The search result can therefore report every starting position and the total number of matches.

1. Theoretical Foundations and Historical Context
Locating multiple occurrences of patterns within extensive literary corpuses has been a core information retrieval challenge since the early days of automated indexing.
The original formulation of string matching frequently focused on decision problems: determining whether a pattern exists within a text.
In practical digital library systems, however, users require exhaustive indexation: discovering every starting index where a query appears.
Donald Knuth addressed multiple occurrences in his seminal 1977 paper by demonstrating how the failure function seamlessly continues search after full matches.
Rather than terminating or resetting pointers to zero, KMP utilizes the longest proper prefix of the entire pattern to advance the search state.
This extension made KMP viable for concordance generation, book indexing, and full-text bibliographical discovery.
Modern digital library search engines rely on multi-occurrence extraction to calculate term frequency (TF) and generate highlighted search snippets.
Exhaustive occurrence discovery powers relevance ranking algorithms and document summary generators.

2. Core Principles, Data Structures, and Invariants
When an exact pattern match is discovered at text index (i - j), the search must proceed to detect subsequent and overlapping occurrences.
Resetting the pattern pointer j to 0 would cause the algorithm to miss valid matches that overlap with the tail of the current match.
The KMP algorithm resolves this by transitioning to j = LPS[m - 1] immediately upon discovering a match of length m.
Because LPS[m - 1] represents the longest proper prefix that is also a suffix of the complete pattern P, this prefix has already matched the text.
The text pointer i continues advancing forward without any backward movement, maintaining the strict O(n) search invariant.
Each discovered match records the starting position (i - j) into an occurrence list.
The occurrence list enables downstream features such as keyword highlighting, snippet extraction, and frequency scoring.
Multi-occurrence search preserves thread safety because multiple worker threads can process disjoint document partitions independently.
The total count of occurrences directly reflects term density, a fundamental metric in information retrieval.
Handling overlapping occurrences correctly is essential in repetitive texts, DNA analysis, and specialized technical catalogs.

3. Mathematical Analysis and Asymptotic Bounds
Let z denote the number of occurrences of pattern P in text T (0 <= z <= n - m + 1).
The time complexity to find all z occurrences remains strictly O(n + m).
The auxiliary space complexity is O(m) for the LPS array plus O(z) to store the starting indices of the matches.
In the worst case, a single-character pattern 'A' searched in a text of n 'A's produces z = n matches.
Even when z = n, the number of character comparisons remains bounded by 2n, confirming optimal linear efficiency.
The distance between consecutive non-overlapping matches is at least m characters.
For overlapping patterns, consecutive occurrences can begin every (m - LPS[m - 1]) characters.
The period of the pattern is defined mathematically as p = m - LPS[m - 1], governing the maximum frequency of occurrences.

4. Algorithmic Procedure and Execution Workflow
Procedure Find-All-Occurrences(T, n, P, m):
  1. Initialize results list positions = [].
  2. Construct LPS = Build-LPS(P, m).
  3. Initialize i = 0 (text index) and j = 0 (pattern index).
  4. While i < n:
       a. If T[i] == P[j]: increment both i and j.
       b. If j == m (complete occurrence found):
            i. Append starting index (i - j) to positions.
            ii. Transition j = LPS[m - 1] to continue searching.
       c. Else if i < n and T[i] != P[j]:
            i. If j > 0: set j = LPS[j - 1].
            ii. Else: increment i.
  5. Return positions list.

5. Concrete Worked Example and Laboratory Trace
Consider Text T = 'AABAACAADAABAABA' (n = 16) and Pattern P = 'AABA' (m = 4).
Pattern LPS construction:
  P = 'AABA' -> LPS = [0, 1, 0, 1]. Length m = 4, LPS[3] = 1.
Search trace:
  - Matches P at T[0..3] ('AABA'). Record starting index 0.
  - Full match at j = 4: update j = LPS[3] = 1. Text pointer is i = 4 ('C').
  - T[4] = 'C' vs P[1] = 'A' -> mismatch. j = LPS[0] = 0.
  - T[4] = 'C' vs P[0] = 'A' -> mismatch. i advances to 5.
  - Matches continue until T[9..12] ('AABA'). Record starting index 9.
  - Full match at j = 4: update j = LPS[3] = 1. Text pointer is i = 13 ('A').
  - Next characters match: T[12..15] ('AABA'). Record overlapping starting index 12.
Final occurrences list: [0, 9, 12].
Notice that occurrence at index 12 overlaps with the occurrence at index 9, correctly detected via LPS[3] = 1.

7. Comparative Analysis and Architectural Trade-offs
Single-Match Search: Stops immediately at first occurrence. Faster early exit, but insufficient for catalog search.
Exhaustive KMP Multi-Match: Finds all z matches in O(n + m) time without restarting the text scan.
Suffix Tree Search: Finds all z occurrences in O(m + z) query time, but requires O(n) construction and 10x-20x more memory.
Inverted Index Search: Instant lookup for single words, but cannot match arbitrary substrings without n-gram expansion.
Regular Expression Engine: Capable of multi-match, but vulnerable to catastrophic backtracking on complex patterns.

8. Common Misconceptions, Pitfalls, and Edge Cases
Setting j = 0 after finding a match, causing failure to detect overlapping patterns like 'ABA' in 'ABABA'.
Allocating an unboundedly large array for match positions rather than a dynamic resizing list.
Failing to check whether i < n after incrementing inside the matching branch, leading to index out-of-bounds errors.
Double-counting matches when case normalization is applied incorrectly during tokenization.
Confusing 0-indexed positions used internally by algorithms with 1-indexed line numbers displayed to library users.

9. Frequently Asked Questions (FAQ)
Q: How does KMP detect overlapping matches?
A: By updating j = LPS[m - 1] after a full match, KMP retains the matching prefix-suffix overlap for the next possible start.
Q: What is the maximum number of occurrences possible in a text?
A: A pattern can occur at most (n - m + 1) times in a text of length n, which happens when both text and pattern consist of identical characters.
Q: Does finding multiple matches increase KMP time complexity?
A: No; appending index positions takes O(1) time per match, preserving the overall O(n + m) bound.
Q: How are multi-occurrence results presented in the digital library UI?
A: The engine highlights each occurrence and displays surrounding context snippets to assist user document evaluation.
