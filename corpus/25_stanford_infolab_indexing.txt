Content: CHAPTER 1: POSTING LIST PROCESSING IN ACADEMIC SEARCH ENGINES
In a university digital library hosting millions of academic articles, evaluating multi-term Boolean and conjunctive queries (e.g. 'quantum' AND 'cryptography' AND 'protocols') requires intersecting the posting lists of the constituent query terms.
Naively, intersecting two sorted posting lists L_1 and L_2 using a two-pointer merge scan requires O(|L_1| + |L_2|) comparisons.
When one posting list is very long (e.g. term 'algorithm' appearing in 100,000 documents) and the other is very short (e.g. 'Needleman-Wunsch' appearing in 40 documents), scanning through all 100,000 entries of the first list is highly inefficient.
Skip Pointers enable the search engine to skip over large non-matching segments of posting lists without reading them from memory.

CHAPTER 2: SKIP POINTER ARCHITECTURE AND OPTIMAL PLACEMENT
A Skip List augmentation adds forward skip pointers to a sorted posting list. Each skip pointer at position i points forward to position i + k and records the DocID at that destination.
Algorithm 1: Intersect-With-Skips(p_1, p_2)
1. Initialize pointers i = 0 for L_1, j = 0 for L_2.
2. While i < |L_1| and j < |L_2|:
     a. If DocID(p_1) == DocID(p_2):
          results.append(DocID(p_1))
          i = i + 1, j = j + 1
     b. Else if DocID(p_1) < DocID(p_2):
          If hasSkip(p_1) and DocID(skip(p_1)) <= DocID(p_2):
              While hasSkip(p_1) and DocID(skip(p_1)) <= DocID(p_2):
                  p_1 = skip(p_1)
          Else:
              p_1 = next(p_1)
     c. Else:
          If hasSkip(p_2) and DocID(skip(p_2)) <= DocID(p_1):
              While hasSkip(p_2) and DocID(skip(p_2)) <= DocID(p_1):
                  p_2 = skip(p_2)
          Else:
              p_2 = next(p_2)
3. Return results.

Theorem 2.1 (Optimal Skip Frequency):
For a posting list of length L, the optimal number of skip pointers is sqrt(L), placed at uniform intervals of sqrt(L) postings.
Proof:
Suppose skip pointers are placed every k postings. The number of skip pointers is L / k.
In the worst-case search for a target DocID:
- We make at most L / k skip pointer comparisons to locate the enclosing interval.
- Once the interval is identified, we make at most k - 1 sequential pointer comparisons to locate the exact DocID.
Total worst-case comparisons C(k) = (L / k) + k.
To find the minimum, take the derivative with respect to k and set to zero:
d C(k) / d k = - L / k^2 + 1 = 0   ==>   k^2 = L   ==>   k = sqrt(L).
Therefore, placing skip pointers at intervals of exactly sqrt(L) minimizes comparisons to at most 2 * sqrt(L).

CHAPTER 3: MODERN BIT-PACKING COMPRESSION: PFOR-DELTA AND SIMD-BP128
While byte-aligned codes (like VByte) are simple, modern search architectures process hundreds of millions of postings per second using hardware SIMD (Single Instruction Multiple Data) vector instructions (AVX-512, NEON).
1. Frame of Reference (FoR):
   Groups postings into blocks of 128 or 256 integers. It subtracts the minimum value in the block from all entries and packs them using the minimum number of bits b required by the maximum value in the block.
2. Patched Frame of Reference (PForDelta):
   If 99% of values in a block fit within b = 4 bits, but one outlier requires 16 bits, standard FoR would force the entire block to use 16 bits. PForDelta encodes the 99% of normal values using 4 bits and stores the rare outliers in an exception patch buffer at the end of the block.
3. SIMD-BP128:
   Unpacks 128 4-bit integers simultaneously into four 32-bit registers in a single CPU clock cycle, delivering decompression throughput exceeding 5 billion postings per second per core.
