Content: CHAPTER 1: THE FINGERPRINTING PARADIGM IN INFORMATION RETRIEVAL
The fundamental challenge of string matching in massive digital repositories is that direct character-by-character comparison requires O(M) time for each candidate text position. If a text has N characters, evaluating N - M + 1 candidate alignment windows naively takes O(N * M) operations.
In 1987, Michael O. Rabin and Richard M. Karp introduced a probabilistic approach known as algorithmic fingerprinting. Rather than comparing characters directly, the algorithm maps strings to numerical fingerprints in a bounded integer field. If the fingerprint of a text window matches the fingerprint of the search pattern, only then is an exact character verification performed.
The computational efficiency of Rabin-Karp hinges on an essential mathematical property: the fingerprint of text window T[i + 1 .. i + M] can be derived from the fingerprint of window T[i .. i + M - 1] in O(1) constant time, without inspecting the intermediate M - 2 characters. This sliding-window calculation is called a 'Rolling Hash'.

CHAPTER 2: MATHEMATICAL FORMULATION OF POLYNOMIAL ROLLING HASHES
Let Sigma be a finite alphabet mapped to integer values {0, 1, ..., B - 1}, where B is the base (typically chosen as 256 for ASCII text or a large prime). Let Q be a large prime modulus chosen to fit within standard word registers while minimizing hash collisions (e.g. Q = 1,000,000,007 or 2^31 - 1).
Definition 2.1 (Horner's Polynomial Evaluation):
For a string S = s_0 s_1 ... s_{M-1}, its polynomial hash value H(S) modulo Q is defined as:
H(S) = ( sum_{k=0}^{M-1} s_k * B^{M - 1 - k} ) mod Q
Using Horner's rule, this can be evaluated recursively in O(M) time:
H_0 = s_0 mod Q
H_k = (H_{k-1} * B + s_k) mod Q    for k = 1, 2, ..., M - 1.

Definition 2.2 (The Rolling Hash Transition):
Suppose we have the hash value H(T[i .. i + M - 1]) of the current text window:
H_current = ( T[i]*B^{M-1} + T[i+1]*B^{M-2} + ... + T[i+M-1]*B^0 ) mod Q
When the sliding window advances by one character to T[i + 1 .. i + M], the oldest character T[i] leaves the window, and the incoming character T[i + M] enters.
The new hash value H_{next} is obtained via:
H_{next} = ( (H_{current} - T[i] * B^{M-1}) * B + T[i + M] ) mod Q
To ensure mathematical correctness under modular arithmetic with negative differences:
H_{next} = ( (H_{current} - (T[i] * H_high) % Q + Q) * B + T[i + M] ) % Q
where H_high = B^{M-1} mod Q is precomputed in O(log M) or O(M) time.
Crucially, this rolling calculation requires only two multiplications, two additions/subtractions, and two modulo operations: strictly O(1) operations independent of M.

CHAPTER 3: ALGORITHM IMPLEMENTATION AND STEP-BY-STEP TRACE
Algorithm 1: Rabin-Karp-Matcher(T, P, B, Q)
Input: Text T of length N, Pattern P of length M, Base B, Prime Modulus Q.
Output: List of starting indices where P matches T.
1. If M > N or M == 0, return empty list.
2. Compute high power multiplier:
     H_high = 1
     For k = 0 to M - 2:
         H_high = (H_high * B) mod Q
3. Compute initial fingerprints for P and the first window of T:
     p_hash = 0, t_hash = 0
     For k = 0 to M - 1:
         p_hash = (p_hash * B + P[k]) mod Q
         t_hash = (t_hash * B + T[k]) mod Q
4. Initialize matches = empty list.
5. For i = 0 to N - M:
     a. If p_hash == t_hash:
          // Potential match detected: verify character-by-character to prevent spurious hits
          If T[i .. i + M - 1] == P[0 .. M - 1]:
              matches.append(i)
     b. If i < N - M:
          // Roll hash to next window
          t_hash = ( (t_hash - T[i] * H_high) * B + T[i + M] ) mod Q
          If t_hash < 0:
              t_hash = t_hash + Q
6. Return matches.

Numerical Example:
Let alphabet be decimal digits (B = 10), modulus Q = 13.
Pattern P = '314' (M = 3).
p_hash = (3*100 + 1*10 + 4) mod 13 = 314 mod 13 = 2.
H_high = 10^2 mod 13 = 100 mod 13 = 9.
Text T = '231415'.
Window 0: '231' -> (231) mod 13 = 10 != 2.
Roll to Window 1: remove '2', add '4'.
t_hash = ((10 - 2*9)*10 + 4) mod 13 = ((10 - 18)*10 + 4) mod 13 = (-80 + 4) mod 13 = -76 mod 13 = 2.
Since t_hash == p_hash (2 == 2), we verify '314' == '314' -> Match confirmed at index 1!

CHAPTER 4: COMPLEXITY ANALYSIS AND COLLISION PROBABILITY
Theorem 4.1 (Average and Best-Case Time Complexity):
If the prime modulus Q is selected uniformly at random from primes in [2, M * N^2], the expected number of false-positive hash collisions is less than 1. The expected running time of Rabin-Karp is O(N + M).
Proof:
A spurious hit occurs when H(P) == H(T[i .. i + M - 1]) mod Q, but P != T[i .. i + M - 1].
Let v(P) and v(T_i) be the integer values of P and T_i. A collision implies that Q divides |v(P) - v(T_i)|.
Since v(P) < B^M and v(T_i) < B^M, their absolute difference is bounded by B^M.
The number of distinct prime factors of an integer X <= B^M is at most log_2(B^M) = M * log_2(B).
If Q is chosen from a set of Pi(K) primes where K >> M * N, the probability that Q divides |v(P) - v(T_i)| is at most (M * log_2 B) / Pi(K) = O(1 / N).
Summing over all N - M + 1 positions, the expected number of collisions across the entire text scan is O(1).
Each non-colliding window takes O(1) rolling hash time. Therefore, average search time is O(N + M).
Theorem 4.2 (Worst-Case Time Complexity):
In the pathological worst-case where all text windows produce identical hash values (e.g. T = 'AAAA...A' and P = 'AAAA' with poor modulus), each window triggers an O(M) character verification, yielding O(N * M) worst-case time. In practice, double-hashing (using two distinct primes Q_1, Q_2) reduces collision probability to near zero.

CHAPTER 5: MULTI-PATTERN SEARCH AND PLAGIARISM DETECTION
In large-scale academic digital library search systems, Rabin-Karp provides unique advantages:
1. Multi-Pattern Dictionary Matching: By inserting the hashes of K different search terms into a hash table or Bloom filter, a document can be scanned for all K patterns simultaneously in O(N + K * M) time.
2. Plagiarism Detection and Fingerprinting: Systems such as MOSS and Turnitin use winnowing algorithms based on Rabin-Karp rolling hashes to extract robust document fingerprints, detecting shared paragraphs and paraphrased citations across hundreds of thousands of research papers.
