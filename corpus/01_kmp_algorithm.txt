Content: CHAPTER 1: HISTORICAL GENESIS AND THE PROBLEM OF ROLLBACK IN STRING RETRIEVAL
The fundamental problem of exact string matching is stated as follows: Given a text string T of length N over a finite alphabet Sigma, and a pattern string P of length M over Sigma (where M <= N), determine all indices i in T such that T[i .. i + M - 1] = P.
In early digital library retrieval systems, naive string search algorithms performed character-by-character comparisons. When a mismatch occurred between text character T[i + j] and pattern character P[j], the naive search pointer in the text was decremented back to i + 1, and the pattern index was reset to 0. In the worst-case scenario (such as searching for the pattern 'AAAB' in a text composed of 'AAAA...AAAA'), the naive algorithm requires O(N * M) character comparisons. This quadratic behavior causes catastrophic latency degradation when indexing large corpora of academic dissertations, patent archives, and digitized manuscripts.
In 1970, James H. Morris and Vaughan R. Pratt independently discovered a method to eliminate text rollbacks by precomputing pattern shifts. Simultaneously, Donald E. Knuth analyzed the problem from the perspective of Cook's theorem on two-way deterministic pushdown automata. Knuth, Morris, and Pratt joined forces to publish their seminal 1977 paper, formalizing the Knuth-Morris-Pratt (KMP) algorithm. The fundamental breakthrough of KMP is the complete elimination of text pointer rollbacks: the text pointer i advances strictly monotonically from 0 to N - 1, guaranteeing deterministic O(N) scan time regardless of alphabet distribution.

CHAPTER 2: MATHEMATICAL FORMULATION OF THE LONGEST PREFIX-SUFFIX (LPS) ARRAY
The core invariant of the KMP algorithm is the Longest Proper Prefix which is also a Suffix (LPS) array, denoted mathematically as pi[0 .. M - 1].
Definition 2.1 (Proper Prefix and Suffix):
A proper prefix of a string S is any prefix of S that is not equal to S itself. A proper suffix of S is any suffix of S that is not equal to S itself.
Definition 2.2 (The Prefix Function pi):
For any pattern P of length M, the prefix function pi: {0, 1, ..., M - 1} -> {0, 1, ..., M - 1} is defined such that:
pi[j] = max { k : k < j + 1 and P[0 .. k - 1] is a suffix of P[0 .. j] }.
In other words, pi[j] is the length of the longest proper prefix of the subpattern P[0 .. j] that is also a suffix of P[0 .. j].
Lemma 2.1 (Prefix Table Monotonicity and Recurrence):
Let k = pi[j - 1]. If P[j] == P[k], then pi[j] = k + 1. If P[j] != P[k], then the next candidate length is recursively given by pi[k - 1]. This recursion terminates when either a matching character P[j] == P[k'] is discovered or k reaches 0.
Proof of Lemma 2.1:
Suppose P[0 .. k - 1] is the longest proper prefix that is also a suffix of P[0 .. j - 1]. If the next character P[j] matches P[k], then P[0 .. k] is an identical prefix-suffix pair for P[0 .. j] of length k + 1. If P[j] != P[k], any shorter valid prefix-suffix of P[0 .. j] must also be a prefix-suffix of P[0 .. k - 1]. By mathematical induction, the longest such candidate is precisely pi[k - 1]. Continuing this chain explores all maximal prefix-suffixes in strictly decreasing order without missing any valid match.

CHAPTER 3: ALGORITHM IMPLEMENTATION AND STEP-BY-STEP TRACE
We present the formal algorithmic specification for both the preprocessing phase and the search phase.

Algorithm 1: Compute-LPS-Array(P, M)
Input: Pattern P of length M.
Output: Integer array lps of length M.
1. Initialize lps[0] = 0, len = 0, and index i = 1.
2. While i < M:
     a. If P[i] == P[len]:
          len = len + 1
          lps[i] = len
          i = i + 1
     b. Else (P[i] != P[len]):
          If len != 0:
              len = lps[len - 1]   // Fallback to previous longest prefix without incrementing i
          Else:
              lps[i] = 0
              i = i + 1
3. Return lps.

Algorithm 2: KMP-Search(T, P)
Input: Text T of length N, Pattern P of length M.
Output: List of 0-based match indices where P occurs in T.
1. If M == 0 or N < M, return empty list.
2. lps = Compute-LPS-Array(P, M).
3. Initialize text index i = 0, pattern index j = 0, matches = empty list.
4. While i < N:
     a. If T[i] == P[j]:
          i = i + 1
          j = j + 1
          If j == M:
              matches.append(i - j)
              j = lps[j - 1]   // Shift pattern according to prefix table to find subsequent overlapping matches
     b. Else (T[i] != P[j]):
          If j != 0:
              j = lps[j - 1]   // Advance pattern without rolling back text index i
          Else:
              i = i + 1        // Advance text index directly
5. Return matches.

Detailed Execution Trace:
Consider pattern P = 'ABABCABAB' (M = 9).
Tracing Compute-LPS-Array:
- i = 0: lps[0] = 0.
- i = 1: P[1]='B' != P[0]='A' -> lps[1] = 0.
- i = 2: P[2]='A' == P[0]='A' -> len = 1, lps[2] = 1.
- i = 3: P[3]='B' == P[1]='B' -> len = 2, lps[3] = 2.
- i = 4: P[4]='C' != P[2]='A' -> fallback len = lps[1] = 0; P[4] != P[0] -> lps[4] = 0.
- i = 5: P[5]='A' == P[0]='A' -> len = 1, lps[5] = 1.
- i = 6: P[6]='B' == P[1]='B' -> len = 2, lps[6] = 2.
- i = 7: P[7]='A' == P[2]='A' -> len = 3, lps[7] = 3.
- i = 8: P[8]='B' == P[3]='B' -> len = 4, lps[8] = 4.
Resulting LPS Table: [0, 0, 1, 2, 0, 1, 2, 3, 4].
When searching in T = 'ABABDABABCABAB', on mismatch at T[4]='D' vs P[4]='C', j reverts to lps[3] = 2 ('AB'), completely avoiding redundant re-scanning of the first two characters.

CHAPTER 4: ASYMPTOTIC COMPLEXITY AND LOWER BOUND PROOF
Theorem 4.1 (Time Complexity):
The preprocessing phase of KMP takes Theta(M) time, and the search phase takes Theta(N) time. The total running time is Theta(N + M) character comparisons in the worst case.
Proof via Amortized Potential Analysis:
Define a potential function Phi = j (the current index into the pattern).
Initially, Phi_0 = 0. In each step of the search loop:
- Case 1: T[i] == P[j]. The text index i increases by 1, and j increases by 1. The potential increases by Delta Phi = +1. The amortized cost is 1 + 1 = 2.
- Case 2: T[i] != P[j] with j > 0. The text index i does not change, but j decreases to lps[j - 1] < j. The potential decreases by Delta Phi = -(j - lps[j - 1]) <= -1. The amortized cost is 1 - (j - lps[j - 1]) <= 0.
- Case 3: T[i] != P[j] with j == 0. The text index i increases by 1, and j remains 0. The potential change is 0. The amortized cost is 1.
Since j is bounded below by 0 and above by M, the total decrease in j cannot exceed the total increase in j. Because j increases by 1 at most N times (once per text character advance), the number of decreasing adjustments to j is also bounded by N. Therefore, the total number of character comparisons across the entire text scan is strictly bounded by 2N.
Theorem 4.2 (Space Complexity):
The auxiliary space required by the KMP algorithm is Theta(M) integers to store the LPS array, which is independent of the text length N.

CHAPTER 5: APPLICATIONS IN DIGITAL LIBRARY ARCHITECTURE
In academic digital library systems like ACM Digital Library, IEEE Xplore, and PubMed, the KMP algorithm serves several mission-critical functions:
1. Stream Ingestion Search: Because the text index i strictly increases and never rolls back, KMP can be executed directly on streaming network sockets, compressed archive unpackers, and disk-mapped buffered streams without buffering the entire document in main memory.
2. Low-Entropy Text Filtering: When scanning digitized documents with repetitive structure (e.g. genomic sequences in bio-informatics dissertations, source code repositories, and mathematical matrices), KMP achieves predictable, jitter-free latency.
3. Integration with CO-1 Signature Dispatcher: When the query length M is moderate (e.g. 5 <= M <= 50) and document entropy H(S) indicates repetitive character distributions, the digital library query planner automatically delegates string search to KMP to ensure optimal throughput.
