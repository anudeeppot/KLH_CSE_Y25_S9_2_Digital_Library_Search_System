Content: CHAPTER 1: ANATOMY OF A DATABASE STORAGE ENGINE
A database storage engine is the low-level software component responsible for reading, writing, and organizing data pages on persistent storage hardware. In digital library infrastructure, storage engines manage book metadata, user borrowing records, full-text inverted indices, and access control policies.
The primary design challenge is bridging the latency gap between fast volatile memory (DRAM with access latency ~50-100 ns) and non-volatile block storage (NVMe SSDs with ~20-100 microseconds, and HDDs with ~5-10 milliseconds).

CHAPTER 2: B+ TREE STORAGE AND SLOTTED PAGE LAYOUT
The B+ Tree is the ubiquitous indexing structure for relational database systems. Unlike binary search trees, B+ Tree nodes have a high branching factor (fan-out of 100 to 1,000 children), keeping tree height low (typically 3 to 4 levels for millions of records).
In a B+ Tree:
1. Internal nodes store only navigation keys and child page pointers.
2. Leaf nodes store the actual data records or record identifiers (RIDs) and are linked in a doubly-linked list to enable fast sequential range scans.

Slotted Page Architecture:
On disk, each B+ Tree node corresponds to a fixed-size disk page (e.g. 4096 bytes). Within the page:
- Page Header: Contains metadata including page ID, free space pointers, transaction LSN, and slot count.
- Slot Array (Line Pointers): Grows from the top of the page downward, containing 2-byte offsets pointing to the start of each variable-length data record.
- Record Data: Grows from the bottom of the page upward.
- Free Space: Sits between the slot array and record data.
When a record is updated or deleted, only its line pointer in the slot array is modified, preventing page fragmentation and maintaining stable external pointer addresses.

CHAPTER 3: THE BUFFER POOL AND PAGE REPLACEMENT POLICIES
Because persistent storage is orders of magnitude slower than RAM, database systems implement an in-memory cache called the Buffer Pool Manager.
The Buffer Pool consists of an array of fixed-size in-memory memory frames and a Page Table mapping page numbers to frame indices.
Page Pinning: When an active query thread accesses a page, its pin count (reference count) is incremented. The buffer pool eviction algorithm cannot evict any page with pin_count > 0.
Cache Replacement Policies:
1. Least Recently Used (LRU): Evicts the page that has not been accessed for the longest time. However, LRU is susceptible to 'sequential scan pollution', where a table scan of a large digital book flushes all hot cache pages out of memory.
2. CLOCK Algorithm: A circular list approximation of LRU using a single use bit per page frame.
3. 2Q (Two-Queue): Maintains two separate FIFO queues—one for pages accessed once and another for pages accessed multiple times—effectively filtering out one-time sequential scans and protecting frequently cited library documents.

CHAPTER 4: MULTI-VERSION CONCURRENCY CONTROL (MVCC)
In a high-concurrency academic library system, hundreds of students concurrently search the catalog while administrators ingest new acquisitions and cataloging updates.
Multi-Version Concurrency Control (MVCC) eliminates read-write lock contention by ensuring that readers never block writers, and writers never block readers.
Under MVCC:
1. When a transaction updates a document record, the storage engine does not overwrite the existing tuple in place. Instead, it appends a new version of the tuple tagged with creation transaction ID (xmin) and expiration transaction ID (xmax).
2. When a reader begins a transaction, it is assigned a Read Snapshot of currently committed transaction IDs. The reader sees a consistent point-in-time view of the database, ignoring uncommitted or newer transactions.
3. Background garbage collectors (Vacuum threads) identify and purge obsolete record versions that are no longer visible to any active transaction snapshot.
